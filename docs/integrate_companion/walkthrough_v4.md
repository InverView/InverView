# 修正内容の確認 - Shaka エラー (7002, 3016) への対応とデフォルト設定

Shaka Player で発生していたマニフェスト解析エラー (7002) および動画再生エラー (3016) に対する改善を行い、デフォルトの Companion URL を設定しました。

## 修正内容の要約

- **デフォルト設定の追加**:
    - `companionUrl` のデフォルト値を `https://companion.tsub4sa.xyz` に設定しました。未設定の状態でも動作が期待できるようになります。
- **再生互換性の向上**:
    - `shaka.Player` の設定で、`avc1` (H.264) および `vp9` コーデックを優先するように構成しました。AV1 コーデックに関連する再生エラー (3016: Format error) を回避しやすくなります。
    - **最新バージョンへの対応**: Shaka Player v5 で廃止された `alwaysStreamText` および `jumpLargeGaps` 設定を削除し、警告が出ないように調整しました。
- **URL 構築の堅牢化**:

    - 設定された Companion URL の末尾に `/companion` が含まれている場合に、二重にパスが付加されないよう調整しました。
- **デバッグ情報の強化**:
    - **レスポンスフィルタの追加**: マニフェストの読み込みに失敗した場合、その応答内容をコンソールに出力するようにしました（XML が正しく返っているか確認可能）。
    - **エラー詳細の表示**: 3016 エラーが発生した際、コーデックやプロキシの問題の可能性を示唆する詳細なメッセージを表示するようにしました。

## 修正後の動作

1. 設定画面で URL を指定しなくても、デフォルトのサーバーが使用されます。
2. 動画の読み込み時に `7002` エラーが発生する場合、コンソールにサーバーからの実際の応答内容が表示されるため、原因の特定が可能です。
3. コーデックの問題で再生できなかった動画が、優先順位の変更により再生できるようになる可能性があります。

## 検証手順

- [ ] 設定を初期化、または `companionUrl` を空にして、デフォルトの `https://companion.tsub4sa.xyz` が使用されることを確認。
- [ ] 動画を再生し、以前エラーが出ていた動画での挙動を確認。
- [ ] エラーが発生する場合、コンソールに `Invalid Manifest Response:` または `Shaka Player Error` と共に詳細なデータが出力されていることを確認。
