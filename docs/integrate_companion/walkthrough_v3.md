# 修正内容の確認 - Companion の URL 判定と認証の強化

DASH マニフェスト内の `BaseURL` が相対パス（`/companion/...`）である場合に、認証ヘッダーが正しく付与されない可能性がある問題を修正しました。

## 修正内容の要約

- **認証対象の判定ロジックの改善**:
    - 設定された `companionUrl` からオリジン（例: `https://companion.tsub4sa.xyz`）を抽出し、そのオリジンで始まるすべてのリクエストに対して認証ヘッダーを付与するようにしました。
    - これにより、マニフェスト内で `/companion/videoplayback` のような相対パスが指定されており、それがブラウザによってフルURLに解決された場合でも、確実に `Authorization` ヘッダーが含まれるようになります。
- **URL 正規化の追加**:
    - `new URL().origin` を使用することで、末尾のスラッシュの有無に関わらず正確なドメイン判定が可能になりました。

## 修正後の動作

1. マニフェスト内の `BaseURL` が `/companion/videoplayback...` の形式であっても、解決後の URL が Companion サーバー上であれば自動的に認証が行われます。
2. ネットワークログで `200 OK` が返っているにも関わらずプレイヤーがエラーを出していた場合、この認証漏れ（または判定漏れ）が原因であった可能性が高いため、解消が期待できます。

## 検証手順

- [ ] 動画を再生し、セグメントリクエスト（`videoplayback`）のヘッダーに `Authorization: Bearer <key>` が正しく含まれていることを確認。
- [ ] プレイヤーがエラーを出さずに再生を継続することを確認。
