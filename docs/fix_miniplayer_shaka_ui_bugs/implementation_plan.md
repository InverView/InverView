# テレポート黒画面バグと再生停止バグの「完全な」修正計画（DOM移動の廃止）

## 目的
ユーザーからの「約3回くらいから発生確率が上がる」「ミニプレーヤーに移動したときに再生が止まる」「完全に直してほしい」という強い要望に応え、ミニプレーヤーと通常プレーヤーの切り替えで動画が壊れるバグを**構造的なレベルから根本的に解決**します。

## 現象の根本原因
これまで、プレーヤー間の移動（テレポート）は、React がコンポーネントを切り替える際に、動画の DOM要素（`<video>`）を「古い場所から取り外し、新しい場所にくっつける（`appendChild` / `remove`）」という物理的な DOM 移動によって実現していました。
しかし、ブラウザの動画エンジン（特に MediaSource API）は、動画要素が一瞬でも DOM ツリーから外れたり、親要素が変わったりすることに非常に弱く設計されています。
DOM の付け替えが発生すると：
1. ブラウザが「動画が画面から消えた」と判断し、強制的に `pause()`（再生停止）を引き起こす。
2. 3回ほど着脱を繰り返すと、動画デコーダーや GPU との接続パイプライン自体が修復不能な状態（クラッシュ）になり、音声は流れるが映像が更新されない「黒画面」状態に陥る。
これらはハック（遅延リフローなど）で軽減することはできても、DOM を移動させ続ける限り、発生確率をゼロ（完全に直す）にすることは不可能です。

## 完全な解決策：オーバーレイ・ポータル方式（DOM移動の完全撤廃）
「動画要素を別の場所に移動させる」のをやめます。
代わりに、**動画要素は画面の裏側（`document.body` 直下の固定コンテナなど）に常に1つだけ配置したまま一切動かさず**、通常プレーヤーやミニプレーヤーの枠（コンテナ）の「位置とサイズ」をプログラムでリアルタイムに計算し、**動画要素の方をその枠の上にピッタリと覆いかぶせる（CSSでの座標移動）**というアプローチに変更します。

これにより、動画要素自体は DOM ツリー内を一切移動しなくなるため、**ブラウザの動画エンジンが破壊されることは原理上100%あり得なくなり**、黒画面フリーズや意図しない再生停止バグが完全に直ります。

## Proposed Changes

### [Video Player Component]
#### [MODIFY] [VideoPlayer.tsx](file:///c:/Users/oronami/Music/invidious_react_client/src/components/VideoPlayer.tsx)
- `videoElement` とそのラッパーを、現在のコンポーネント内（`containerRef`）に `appendChild` する処理を廃止。
- 代わりに `document.body` 直下に専用のグローバルホスト要素（例: `div#inverview-global-video-host`）を作成し、そこに動画要素を固定。
- `VideoPlayer` コンポーネント内で `ResizeObserver` とスクロール/ウィンドウリサイズイベントを監視。
- 現在マウントされている（アクティブな）`VideoPlayer` の空枠（`containerRef`）の画面上の座標（`getBoundingClientRect()`）を取得し、グローバルな動画要素の `position: fixed; left, top, width, height` をリアルタイムでそれに一致させる。
- 不要になった遅延描画キックや `visibility` のトグル処理、`isTeleporting` などの複雑なガード処理をすべて削除し、コードをクリーンアップ。

## Verification Plan
1. 動画を再生し、ミニプレーヤーと通常プレーヤーを何十回（連打を含む）行き来させます。
2. DOM 着脱が行われなくなるため、どれだけ切り替えても再生が一瞬たりとも停止せず、黒画面フリーズも一切発生しないことを確認します。
3. スクロール時やウィンドウのリサイズ時に、動画が枠にピッタリ追従して表示されるか（ズレがないか）を確認します。
